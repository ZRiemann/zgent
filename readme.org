* zgent

[[file:doc/en/readme.org][English Documentation]] | [[file:doc/zh-CN/readme.org][中文文档]]

zgent is a user-led ZetaX project for developing a code framework and
validating ideas. The user owns the core framework, key logic, and design
direction, with the goal of understanding the implementation in full.
Agents support this work through auxiliary code, documentation, build
integration, and focused verification.

** Why a separate project?

zeta_agent is developed and maintained primarily by agents, which places a
significant review burden on the user. zgent establishes a different way of
working: the user builds and understands the main framework, while agents
help complete supporting work around the user's direction.

zeta_agent provides reference material; zgent's architecture, features, and
delivery direction remain user-led.

** Current state

The C++ application runtime is built on =zpp=. A =z::server= subclass owns
=z::nng::nng= for external communication and a small application-local HPX
runtime owner for business work. The project main calls =configure()= and
blocking =run()=; the service remains active until shutdown. Agent-specific
business logic and Vault/API key requests have not been implemented.

Focused CTest process tests cover configuration, signals, startup failures,
and cleanup errors. Existing build artifacts alone do not establish current
build or runtime acceptance.
The current version is recorded in [[file:VERSION][VERSION]].
See [[file:release_history.org][Release history]] and [[file:doc/zh-CN/release_history.org][中文发布历史]] for changes and
verification limits.

** Quick start

Prepare the matching Forge dependency environment and installed zpp package
as described in [[file:BUILD.org::*Prerequisites][Build prerequisites]], then run from the zgent checkout:

#+begin_src sh
./zbuild.py list
./zbuild.py doctor
./zbuild.py build --profile release
./zbuild.py run --profile release
#+end_src

=run= uses an existing executable; =dev= builds and runs once. Stop the
foreground service with Ctrl-C. See [[file:BUILD.org][BUILD.org]] for lifecycle ordering,
verification scope, command semantics, paths, and cleanup scope.

** Repository layout

- =src/zgent/= : application entry and server subclass; =zgent_core= and =zgent= targets.
- =include/= : currently empty; reserved for interfaces when needed.
- =tests/= : isolated runtime process tests and a lifecycle failure probe.
- =builder/= and =zbuild.py= : project build definition and thin Forge entry.
- =doc/zgent_conf.json= : development logging and NNG runtime configuration.
- =doc/zgent_hpx.ini= : HPX business runtime configuration.
- =doc/en/= and =doc/zh-CN/= : English primary and Simplified Chinese documentation.
- =BUILD.org= : shared build and runtime reference for both languages.
- =release_history.org= : English release history, with a Chinese translation under =doc/zh-CN/=.
- =AGENTS.md= : ZetaX guidance and zgent collaboration rules.

** Project conventions

zgent follows all ZetaX conventions and constraints. Forge owns shared
build tooling and dependency management; zpp owns reusable C++ infrastructure;
zsa owns deployment and operations; zgent owns its application logic.

See [[file:doc/en/development.org][Development guide]], [[file:doc/zh-CN/development.org][中文开发指南]], and
[[file:AGENTS.md][Agent guidance]] for collaboration and change boundaries.
